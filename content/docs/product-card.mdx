## Usage

```tsx

  ProductCard,
  ProductCardContent,
  ProductCardHeader,
  ProductCardMetric,
  ProductCardSubtitle,
  ProductCardTitle,

  <ProductCardContent>
    <ProductCardHeader>
      <ProductCardTitle>Twemco Clock</ProductCardTitle>
      <ProductCardSubtitle>Clock</ProductCardSubtitle>
    </ProductCardHeader>
    <ProductCardMetric>$219</ProductCardMetric>
  </ProductCardContent>
</ProductCard>
```

## Animated images

A GIF has no play control, so a card that should be still until you point at
it swaps the source instead: a still frame at rest, the animation from frame
one on hover. The handlers reach the well because every part of the card
spreads the DOM props it is given.

<ComponentPreview name="product-card-animated" padding="compact" />

## Overlays

A tag, a save button, a label, an action cluster: each is an overlay in one
corner of the well. `reveal="hover"` hides one until the pointer arrives, but
only on a device that can hover; a touch screen sees every control from the
start. Leave `src` off the image well and it becomes a stage for a widget
instead of a picture.

## Preparing images

The best product images are ones cut out from their background.

On macOS, right-click the file in Finder and choose **Quick Actions → Remove
Background**. If it isn't there, add it under **Customize** — see Apple's
[guide to Quick Actions in the
Finder](https://support.apple.com/guide/mac-help/perform-quick-actions-in-the-finder-mchl97ff9142/mac).

## Override Styling

Every part takes its own `className`, merged last through `tailwind-merge`, so a
utility that conflicts with a default replaces it instead of stacking with it.
The card's type size is set once on the root and inherited by the title,
subtitle and metric, so one `text-*` moves the whole block.

<ComponentPreview name="product-card-override-styling" padding="compact" align="top" />

Parts you hold no reference to are reachable by `data-slot`:

| Slot | Element |
| --- | --- |
| `product-card` | The card root |
| `product-card-image` | The square image well |
| `product-card-img` | The `<img>` inside it — or use `imageClassName` |
| `product-card-overlay` | A corner overlay; `data-position` names the corner |
| `product-card-content` | The row holding the header and the metric |
| `product-card-header` | The title and subtitle group |
| `product-card-title` | The product name |
| `product-card-subtitle` | The secondary line |
| `product-card-metric` | The trailing value |

`size` caps the card's width; a `w-*` or `max-w-*` in `className` overrides that
cap outright, which is what the grid above relies on.

The image well has one ground in every state, so `bg-stone-200` on
`ProductCardImage` recolours it outright. A well that should react to the
pointer adds its own `hover:` utility.

## Accessibility

The root is a `div`, not a control. Passing `onClick` gives it a pointer cursor
but no keyboard access — for a card that must be reachable by keyboard, put a
real `<a>` or `<button>` on the title and stretch it over the card with
`after:absolute after:inset-0`, the way the grid example wraps each card in a
link, which nesting a control inside `role="button"` would not allow.
