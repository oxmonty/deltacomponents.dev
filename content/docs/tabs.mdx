## Usage

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@/components/ui/tabs";

<Tabs defaultValue="account">
  <TabsList>
    <TabsTrigger value="account">Account</TabsTrigger>
    <TabsTrigger value="password">Password</TabsTrigger>
  </TabsList>
  <TabsContent value="account">Manage your account settings.</TabsContent>
  <TabsContent value="password">Change your password here.</TabsContent>
</Tabs>
```

## Override Styling

The list carries the only height and the only type size in the strip. Triggers
stretch to the first and inherit the second, and the indicator insets to the
list's own padding, so `className="h-11 text-sm"` on `TabsList` moves the whole
control the way a `size` step does — `size` is a preset for those same values,
not a separate axis.

<ComponentPreview name="tabs-override-styling" align="top" />

Radius rides the shape system rather than a utility: a `data-radius` scope
gives the list the container radius and the triggers the element radius, which
differ by exactly the list's 4px padding, so `concentric` corners stay nested
without any arithmetic at the call site.

Parts you hold no reference to are reachable by `data-slot`:

| Slot | Element |
| --- | --- |
| `tabs` | The root wrapper |
| `tabs-list` | The strip |
| `tabs-trigger` | One tab |
| `tabs-indicator` | The active pill, or the underline bar |
| `tabs-hover` | The underline variant's hover wash |
| `tabs-content` | One panel |

### TabsContent

A panel mounts the first time its tab becomes active, then stays
mounted — hidden, not unmounted, when another tab is selected — so
content backed by an API doesn't refetch and flash empty on every
revisit. `forceMount` mounts every panel up front instead of waiting
for a first visit.

<PropsTable props={contentProps} />

### TabsFromArray

The same tabs, driven by an array of `TabItem` objects instead of
JSX — for a list that comes from a config or an API rather than
being written out by hand.
